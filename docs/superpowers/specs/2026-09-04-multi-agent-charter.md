## 1. 宪法：Python 指挥官原则

所有分工、路由、投票、聚合、预算、停机规则 = **预注册的确定性代码**。agent 是**有界专家**：

1. 结构化输入 / 结构化输出（各线契约不变）
2. 无 DB 写权（落库归 Python 侧）
3. 禁发明数字（只产定性判断/标签/引用）

§1.4「agent 永远不当大脑」**不动**。多 agent 体系是其延展：**大脑是预注册的聚合规则，agent 是感官**。被否决的「agent 指挥官」（meta-agent 动态决定调谁/信谁）记入 §7，不因本总纲复活。

## 2. 测量纪律（每个多 agent 系统强制自带，缺一不立项）

1. **成员级计分**：每个成员的输出单独落库、单独评测——错误可归因到成员
2. **三对照**：聚合体 vs 最优单体 vs 基线（线 P / 市场收盘）；缺基线的对照不算数
3. **分歧即数据**：成员分歧率与错误率的相关性是核心产出（高分歧场次 = 困难场识别器）
4. **全程审计**：预算消耗、轮数、否决次数落库——这是混合阶段的准入数据

## 3. 混合演进门控（预注册）

「agent 有限裁量」（如 critic 否决带比例上限、成员加权）仅当**同时**满足才可试点：

1. Python 指挥官模式下，聚合体**稳定**优于最优单体（≥2 个评估窗口）
2. 成员分歧率与成员错误率显著相关（裁量有信息可依）
3. 裁量试点自带独立 A/B 与预算上限

## 4. 共享基建策略（反 YAGNI）

**不预建编排框架。** ①（retro ensemble）把编排原语内联实现；②（线 A 集成投票）落地时若出现重复，再提取 `src/fa/orchestration/`。spec 层现在只统一协议词汇：

| 词汇 | 含义 |
|---|---|
| member | 一次有界 agent 调用（attributor=1..N） |
| aggregate | 确定性聚合产物（attributor=0） |
| budget | 预注册的调用/轮数/金额上限 |
| agreement | 成员间一致性度量（多数/全同/无多数） |

## 6. 与各线分账的接口

- ①产出只进 `retro_attributions`（A 线研究），永不进 B 线推荐/落注流——承袭 retro spec §2
- ②产出只进 `agentline_predictions`（`line='A_multi'`），永不进 B 线——承袭双路线 §2
- 两线各自评测各自的聚合体；跨线比较只发生在**报告层**（同批场次、同判据），不共享落库

## 8. 非目标

- 不做 agent 指挥官 / meta-agent 动态路由
- 不预建统一编排框架代码（等两个实例再提取）
- 不改 M4/M6 的单兵设计
- 不给任何多 agent 通路接触 B 线推荐/落注流
- 真实下注依然禁止（§7.2）
