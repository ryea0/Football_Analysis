双路线一期测「单 agent 当大脑 vs 确定性管线」；本设计预注册**二期的三个多 agent 形态**，测「多 agent 大脑的增量」。全部遵循总纲：Python 指挥官、成员级计分、三对照、预算审计。

## 2. 门控（gated-1，预注册）

## 3. 形态一：集成投票制（唯一预批准的实施位）

### 3.1 结构

```
信息集 JSON（同一份，复用一期 fa agentline export）
   ├─ 成员 1..3：独立 dsh headless 会话 → 全契约预测 JSON
   └─ Python 聚合（确定性，预注册）→ A_multi 聚合行
落库 agentline_predictions：line='A_multi'，成员 attributor=1..3、聚合 attributor=0
```

### 3.2 聚合规则（确定性）

| 字段 | 规则 |
|---|---|
| p_home / p_draw / p_away | 成员**分量中位数** → 三项和归一（沿用一期归一规则与容差审计） |
| p_over25 | 成员值中位数（单值无归一需求，口径与一期单 agent 一致） |
| confidence | 中位数 |
| sources | URL 去重并集 |
| reasoning_digest | 与聚合概率向量 **KL 距离最小**的成员的 digest（确定性平票取 attributor 序最小） |
| status | 可用成员 k=0 → 'error'（或成员失败多数态）；k≥1 → 'ok' |
| parse_fail | 任一成员 parse_fail 不影响聚合（k≥1 即可聚），成员行如实记 |

### 3.3 评测（五对照 + 成员级）

线 P / A_base / A_enh / **A_multi** / 市场（Pinnacle 收盘）同批同判据（复用 backtest/metrics.py 与一期 compare）；**成员 1..3 各自单独计分**（纪律 1）——「聚合体 vs 最优单体」直接可算（纪律 2 的前提）。

### 3.4 成本

单场 = 3 次 dsh 会话（一期成本的 ×3）；周批规模沿用一期扩批节奏，先 30-50 场/批复盘成本再放量。

## 4. 形态二：角色分工制（预注册扩展位，gated-2）

```
联赛专家（定性候选+理由）→ 风控官（仓位上限审查）→ 复盘官（供给历史相似案例）
                    ↑ Python 指挥官按跳分配预算、校验契约、落库每跳中间产物
```

- **Python 指挥 agent 串**——不违反旧否决（D3 修订）；无任何 agent 调度 agent
- 每跳中间产物落库（新表届时定，风格对齐 agentline_runs）：错误可归因到跳
- 各跳契约独立预注册；任何一跳失败 → 该场降级为「跳前最后可用产物」并落 status
- 门控：形态一数据齐 + 形态一显示「聚合增益有限但定性信息有增量」（分工制才有意义）

## 5. 形态三：辩论修订制（预注册扩展位，gated-2）

```
生成者出预测 → 批评者攻击（弱点/替代解释）→ 生成者修订（≤2 轮）
预算硬上限：轮数×N 次调用，超限取末版并落 budget_exhausted 标记
```

- 轮数与每轮产物全落库（轮数本身是难归因变量，故强制预算上限）
- 门控：形态一数据齐；辩论制成本 ≈ 形态一 ×(1+轮数)，须先有形态一的成本-收益基线

## 6. 附录：给 agentline 原会话的建表建议（一期实施时一次到位）

`agentline_predictions` 尚未建表。为避免「SQLite 无法后补 CHECK」的返工（retro 的教训），**一期建表时**请直接包含：

1. `line` CHECK 词表：`('A_base', 'A_enh', 'A_multi')`——`A_multi` 为二期预留，不实施也不占迁移
2. `attributor INTEGER NOT NULL DEFAULT 1` 列（成员 1..3、聚合 0）——无 CHECK 可后补，但一次到位免 ALTER
3. 本建议不改变一期任何行为（A_multi 只是词表占位）

## 7. 非目标

- 不做 agent 指挥官 / meta-agent 路由（总纲 D2）
- 不做异构模型成员、自动加权（gated-3 混合门控的前提数据先攒）
- 不给任何多 agent 通路接触 B 线推荐/落注流；真实下注禁止
- 本设计不驱动一期实施（D4 分工：一期归原会话）

## 8. 风险与开放问题

| 风险/开放 | 处置 |
|---|---|
| dsh developer preview，CLI 契约可能变（承袭一期风险） | 聚合在 Python 侧，dsh 契约变化只影响 runner 单点 |
| 同模型 3 次采样相关性 → 集成增益可能≈0 | 这正是要测的；一期 A_base 与 A_multi 的差即「采样集成」的净效应，如实报告 |
| 五对照的多重比较（样本量分配） | 评测沿用一期滚动报告口径，比较面在报告预注册，不做事后挑选 |
| 开放：N 是否随批次自适应 | 否——预注册固定 3，自适应 N 属混合裁量（gated-3） |
