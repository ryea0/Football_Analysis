## 3. 形态一：集成投票制（唯一预批准的实施位）

### 3.1 结构

```
信息集 JSON（同一份，复用一期 fa agentline export）
   ├─ 成员 1..3：独立 dsh headless 会话 → 全契约预测 JSON
   └─ Python 聚合（确定性，预注册）→ A_multi 聚合行
落库 agentline_predictions：line='A_multi'，成员 attributor=1..3、聚合 attributor=0
```

### 3.2 聚合规则（确定性）

| 字段 | 规则 |
|---|---|
| p_home / p_draw / p_away | 成员**分量中位数** → 三项和归一（沿用一期归一规则与容差审计） |
| p_over25 | 成员值中位数（单值无归一需求，口径与一期单 agent 一致） |
| confidence | 中位数 |
| sources | URL 去重并集 |
| reasoning_digest | 与聚合概率向量 **KL 距离最小**的成员的 digest（确定性平票取 attributor 序最小）。**KL 零质量规则（预注册 2026-09-04 AM-T2 审查）**：聚合向量某分量为 0 而成员该分量 >0 时 KL=∞（该成员永不当选最近）；三中位全 0（聚合退化）→ 聚合行 status='error'，digest「聚合退化（k>0，中位和为 0）」——聚合层镜像契约侧对零和的拒绝语义，绝不抛异常 |
| status | 可用成员 k=0 → 'error'（或成员失败多数态）；k≥1 → 'ok' |
| parse_fail | 任一成员 parse_fail 不影响聚合（k≥1 即可聚），成员行如实记 |

### 3.3 评测（五对照 + 成员级）

线 P / A_base / A_enh / **A_multi** / 市场（Pinnacle 收盘）同批同判据（复用 backtest/metrics.py 与一期 compare）；**成员 1..3 各自单独计分**（纪律 1）——「聚合体 vs 最优单体」直接可算（纪律 2 的前提）。

### 3.4 成本

单场 = 3 次 dsh 会话（一期成本的 ×3）；周批规模沿用一期扩批节奏，先 30-50 场/批复盘成本再放量。

## 4. 形态二：角色分工制（预注册扩展位，gated-2）

```
联赛专家（定性候选+理由）→ 风控官（仓位上限审查）→ 复盘官（供给历史相似案例）
                    ↑ Python 指挥官按跳分配预算、校验契约、落库每跳中间产物
```

- **Python 指挥 agent 串**——不违反旧否决（D3 修订）；无任何 agent 调度 agent
- 每跳中间产物落库（新表届时定，风格对齐 agentline_runs）：错误可归因到跳
- 各跳契约独立预注册；任何一跳失败 → 该场降级为「跳前最后可用产物」并落 status
- 门控：形态一数据齐 + 形态一显示「聚合增益有限但定性信息有增量」（分工制才有意义）

## 5. 形态三：辩论修订制（预注册扩展位，gated-2）

```
生成者出预测 → 批评者攻击（弱点/替代解释）→ 生成者修订（≤2 轮）
预算硬上限：轮数×N 次调用，超限取末版并落 budget_exhausted 标记
```

- 轮数与每轮产物全落库（轮数本身是难归因变量，故强制预算上限）
- 门控：形态一数据齐；辩论制成本 ≈ 形态一 ×(1+轮数)，须先有形态一的成本-收益基线

## 9. E2E 实测（首批 30 场，2026-09-04，AM-T5）

> 预写解读规则（执行前已定，不事后追加）：**聚合未优于最优成员不构成失败**——多 agent 增益本来就是要测的命题；且 n=30 无统计意义，本节全部数字只作**管线可用性证据**，不构成方向性结论。

### 9.1 运行事实

- 命令：`fa agentline run --line A_multi --limit 30`（members=3 默认），活库直跑（`FA_DB=<repo>/data/fa.db`，schema v7）。`fa init` 先行幂等通过、存量 200 行保全（A_base/A_enh 各 100 ok）——v6→v7 重建已在 AM-T1 落地，本次 init 为幂等空跑，无影子表残留
- 样本：一期 100 场信息集中 match_id 最小的 30 场（E0 2023 ×20、SP1 2023 ×10，赛期 2023-09-23 ~ 2024-05-15，历史回放）。与 A_base 的 100 场完全重合 → 聚合 vs A_base 为**同子集配对**比较（30/30 有 A_base ok 行）
- 台账：`agentline_runs` #3 `A_multi ok=30 parse_fail=0 timeout=0 error=0`；run summary 的 info_dir 经 worktree 符号链接指向同一活库 `data/agentline/`（审计时可辨）
- 成员行：90 行（30 场 × 3 员）status 全 ok → **成员契约率 90/90 = 100%**；其中 repaired（直解失败、救援提取成功）40/90 = 44.4%（三员分别为 15/12/13）——status 仍 ok，只作契约观测
- 成员 sources 全空（成员用 A_base prompt，无检索）→ 聚合 sources 并集为空，符合 §3.1 结构预期
- 耗时：90 次 dsh 会话合计 45.9 min（均值 30.6s / 中位 27.5s / 最大 79.9s）；墙钟 17:22:38 → 18:08:33 = **45 分 55 秒**；聚合行 duration_s 记三成员合计（均值 91.8s/场）

### 9.2 五对照（口径：自然对数 log-loss，市场=Pinnacle 收盘去水，同 metrics.evaluate）

| 线 | n | ll | Brier | 子集市场 ll | vs 子集市场 |
|---|---|---|---|---|---|
| A_multi（聚合） | 30 | 1.0436 | 0.3141 | 1.0636 | 0.981× |
| A_base（同子集） | 30 | 1.0564 | 0.3192 | 1.0636 | 0.993× |
| 市场 | 30 | 1.0636 | 0.3222 | 1.0636 | 1.000× |
| （参照）A_base 全 100 场 / A_enh 全 100 场 | 100 | 0.9469 / 0.9351 | — | 0.9484 | 0.998× / 0.986× |

平注 ROI（compare 报告输出）：A_multi n=14 roi=+35.5%——n=14，纯噪声量级，不得引用为优势证据。

本 30 场子集市场 ll（1.0636）明显差于全样本（0.9687）——子集偏难偏噪，跨线直比无效（沿用滚动报告脚注口径）。

### 9.3 聚合 vs 最优成员（手工 SQL 口径）

口径：成员行（attributor=1..3）join backtest_predictions 逐行算单场 log-loss（自然对数、概率 clip 1e-12）；**oracle 最优成员** = 每场在该场 ok 成员中取单场最小 ll、再对 30 场求均值——**事后选择，是上界不是可实现策略**。本批三成员全 ok，子集即全 30 场。

| 对象 | ll | Brier |
|---|---|---|
| 成员 1 | 1.0503 | 0.3165 |
| 成员 2 | 1.0613 | 0.3196 |
| 成员 3 | 1.0210 | 0.3057 |
| **聚合（分量中位数）** | **1.0436** | **0.3141** |
| oracle 最优成员 | 0.9930 | — |
| oracle 最差成员 | 1.0960 | — |

- 聚合落在成员区间内（3 员中排第 2：优于 2 员、劣于最优 1 员 0.023 ll）
- 聚合单场 ll 优于成员均值 15/30；优于该场最优成员 0/30——中位数对坏样本的平滑是双向的，不产生逐场打败最优成员的能力
- 成员多样性：两两 |p| L1 距离均值 0.0656（0=完全同判、上限 2）；30/30 场三成员概率向量互不相同——同模型 3 次采样确实产生差异（§8 风险行的实证），但幅度小，这解释了集成增益有限

### 9.4 显著性核查（诚实条款）

配对单场 ll 差（n=30）：聚合−市场 均值 −0.0200（sd 0.0981，se 0.0179，t=−1.11，~95%CI −0.0550 ~ +0.0151）；聚合−A_base 均值 −0.0127（se 0.0152，t=−0.84，CI 跨 0）。**两个差异都与 0 不可区分**——本批不支撑「聚合优于市场/A_base」的任何主张，仅证明：A_multi 全链路（3 成员独立会话 → 确定性聚合 → 三元组落库 → 五对照可评）可用且无失败。

### 9.5 成本与放量

单场 = 3 次 dsh 会话 ≈ 1.6 min 墙钟（§3.4 的 ×3 预估成立）；外推 100 场/批 ≈ 46 min 墙钟、无失败重试成本。放量节奏仍按 §3.4：先复盘本批成本-收益，再定是否扩批；聚合是否换成/加选均值、修剪均值等变体属**未预注册**改动，须先回到设计层。
